# test/e2e — checking in a real browser with headless Chromium

What the unit tests (`node --test test/*.test.js`, `./test/run-relay.sh`) cannot reach — the pages, the relay and Xipe Totec working
together — is checked by driving headless Chromium over CDP (the Chrome DevTools Protocol). It needs only node (its built-in WebSocket),
`chromium` and the development shell (<!-- env:nix -->`nix develop`<!-- /env:nix -->).

**It never touches the real environment**: the pages, the relay, a copy of Xipe Totec, a fake Xipe server and Chromium run on other ports.
`:4000` (Emacs), `:4100` (the relay), `:4001` (the pages) and xipe_totec's own `tables/` are not used (xipe_totec keeps its state relative to
`__DIR__`, so a copy is made and that one runs).

## Stand-ins in headless mode (worth knowing)

What does not happen headless is replaced by events the browser itself would fire:

- **Copying**: Ctrl+C by CDP key input does not copy → a `copy` event is dispatched directly
- **Window focus**: switching tabs fires no `focus` → scenarios needing it dispatch `focus` (e.g. checking `compile.run`'s "window
  focused last")
- **Background tabs**: xterm.js draws with `requestAnimationFrame`, so a background tab's screen is not updated → `Page.bringToFront` before
  reading

## Adding a scenario

Use `openPage(url)`, `attachTo(part of the URL)` (to attach to a window opened by `window.open`), `p.eval(expr)`, `p.waitFor(expr)`,
`p.key(key, code, text, modifiers)`, `check(condition, what)` and `done()` from `cdp.mjs`. Panels inside a skin are same-origin iframes, so
the parent page reaches them through `contentDocument`.
